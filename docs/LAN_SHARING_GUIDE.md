# 局域网二维码分享指南（Windows · M1）

日期：2026-10-24。适用版本：`fix/m1-lan-qr-sharing` 分支及之后。目标：电脑上发布问卷 → 生成局域网链接 + 本地二维码 → 手机扫码填写 → 数据进电脑 MySQL。**不使用公网服务器、内网穿透或在线二维码服务。**

## 0. 一分钟总览

```
电脑（Windows）                          手机
┌─────────────────────────┐            ┌──────────┐
│ Spring Boot 127.0.0.1:8080│            │          │
│        ↑ 代理 /api        │   Wi-Fi/   │  扫码 →  │
│ Vite dev:lan 0.0.0.0:5173│   电脑热点   │  填写提交 │
└─────────────────────────┘ ←────────── └──────────┘
```

手机只访问 Vite 的 5173 端口；后端 8080 与 MySQL 3306 仍只监听本机，不向局域网暴露。

## 1. 启动局域网模式

```powershell
# 终端 A：后端（保持原样，仅本机）
.\scripts\Start-Backend.ps1 -JavaHome 'D:\jdk\jdk17'

# 终端 B：前端局域网模式（新增）
Set-Location .\frontend
npm.cmd run dev:lan
```

`dev:lan` 与原 `npm.cmd run dev` 的唯一区别是监听 `0.0.0.0:5173`（所有网卡）而不是 `127.0.0.1:5173`。日常独自开发继续用 `dev`；需要手机扫码时才用 `dev:lan`。

启动后 Vite 会打印多个 Network 地址，例如 `http://192.168.137.1:5173/`。

## 2. 查看电脑的局域网 IPv4

任选其一：

```powershell
# 方法 1：PowerShell（推荐，直接过滤出可用 IPv4）
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object IPAddress, InterfaceAlias
```

```powershell
# 方法 2：经典命令，在输出里找“IPv4 地址”
ipconfig
```

```powershell
# 方法 3：登录网站后在“局域网分享设置”里直接点选（GET /api/system/lan-addresses 检测）
```

典型取值：家庭 Wi-Fi 下是 `192.168.x.x`；开启 Windows 移动热点后热点网卡通常是 `192.168.137.1`。**不要选 `127.x`、`169.254.x` 或虚拟机专用网段上手机不通的地址。**

## 3. 配置网站里的局域网地址

1. 打开 <http://127.0.0.1:5173>，登录，进入问卷编辑页。
2. 发布（或轮换）后，“分享已发布版本”面板出现“局域网分享设置”。
3. 输入或点选电脑 IPv4 → 保存。二维码与“手机局域网链接”立即生成，例如：
   `http://192.168.137.1:5173/public/<43位Token>`
4. 面板提供：**复制局域网链接 / 下载二维码 PNG / 打开答题页**；下方另附“本机预览”链接（127.0.0.1，仅供本机，手机打不开）。
5. 地址只保存在当前浏览器（localStorage）。换网络（家 ↔ 热点）后改一下再保存即可，所有二维码自动重生成。
6. 未配置或填了 `localhost/127.0.0.1/0.0.0.0` 时不会生成二维码，而是提示先设置——避免生成手机扫不开的码。

## 4. 手机如何与电脑组网（三种场景）

### 场景 A：手机连电脑开的移动热点（推荐，IP 最稳定）

1. Windows 设置 → 网络和 Internet → 移动热点 → 开（“通过 Wi-Fi 共享我的 Internet 连接”）。
   快捷打开：`Start-Process ms-settings:network-mobilehotspot`
2. 手机 Wi-Fi 列表连接该热点（默认名/密码在同一页面）。
3. 电脑热点网卡地址通常固定为 `192.168.137.1`——在网站里配置它即可。
4. 此场景下电脑可能无 Internet（若宽带走 Wi-Fi 会被热点抢占），问卷功能不受影响（全部本地）。

### 场景 B：电脑与手机连同一个 Wi-Fi

1. 手机与电脑连入同一 SSID。
2. 用第 2 节方法确认电脑在该 Wi-Fi 里的 IPv4（常见 `192.168.1.x` / `192.168.0.x`），配置进网站。
3. 注意 DHCP：路由器重启或设备重连后电脑 IP 可能变化，二维码随之失效，重新查 IP 并保存即可。

### 场景 C：电脑连手机热点（手机流量）

1. 手机开热点，电脑 Wi-Fi 连接它。
2. 电脑会拿到手机分配的 IPv4（查看方法同第 2 节），配置进网站。
3. 此场景手机自身访问“自己热点里的电脑”一般可行，但个别机型对热点内回环访问有限制；若不通改用场景 A。

**客户端隔离提示**：部分路由器/热点开启了“AP 隔离/客户端隔离”，同网设备互相不可见。症状为：手机能上网但打不开电脑 IP。解决：路由器管理页关闭 AP 隔离，或改用场景 A（电脑热点）。本项目不保证所有热点环境必然互通。

## 5. Windows 防火墙（只放行前端端口）

`dev:lan` 首次启动时 Windows 可能弹出“允许访问”对话框——勾选“专用网络”并允许即可。若没弹窗或被拒，手动加规则（**管理员 PowerShell**）：

```powershell
# 添加：仅专用网络配置文件、仅 TCP 5173
New-NetFirewallRule -DisplayName "ZhiYan Vite 5173 LAN" `
  -Direction Inbound -Protocol TCP -LocalPort 5173 -Profile Private -Action Allow

# 查询
Get-NetFirewallRule -DisplayName "ZhiYan Vite 5173 LAN"

# 不再需要时删除
Remove-NetFirewallRule -DisplayName "ZhiYan Vite 5173 LAN"
```

确认当前网络是“专用”（设置 → 网络和 Internet → 属性 → 网络配置文件 = 专用）。

```powershell
Get-NetConnectionProfile | Select-Object Name, NetworkCategory
# 若显示 Public，可改（把 MyWiFi 换成上面的 Name）：
Set-NetConnectionProfile -Name "MyWiFi" -NetworkCategory Private
```

**只放行 5173。不要为 8080（后端）或 3306（MySQL）加放行规则**——它们由 Vite 代理在本机转发，无需暴露。

## 6. 手机扫码验证

1. 手机相机或微信“扫一扫”扫描页面二维码（或手动输入局域网链接）。
2. 应看到问卷标题与“参与与数据用途说明”，勾选同意 → 开始填写。
3. 填写 → 点“保存进度” → 手动刷新页面：已保存答案应恢复。
4. “确认提交答卷” → 出现“提交成功”页；刷新仍是成功页且不新增回收数。
5. 电脑端编辑页“查看版本统计”应看到新增的 1 份回收。

若手机打不开：① 确认仍在同一网络；② 重新查电脑 IP（可能已变）；③ 检查防火墙规则与网络类别；④ 排查 AP 隔离（见第 4 节）。

## 7. 为什么手机不能访问 localhost / 127.0.0.1

`localhost` 是“每台设备自己”。二维码里若写 `http://127.0.0.1:5173/...`，手机扫码后访问的是**手机自己**的 5173 端口——自然打不开。因此本项目的二维码只允许配置电脑的局域网 IPv4（或将来公网域名），填写 `localhost/127.0.0.1/0.0.0.0` 会被直接拒绝并提示。

## 8. 离开局域网 / IP 变化 / 服务停止后的表现

- **手机离开该 Wi-Fi/热点**：二维码与链接失效（连接超时）。已提交数据安全存于电脑 MySQL；未提交的会话保留在数据库 7 天，回到同一网络、同一链接、同一手机浏览器标签页可继续（匿名会话凭证在标签页 sessionStorage 中，清理标签页数据后无法找回，这是 M1 既有限制）。
- **电脑 IP 变化**（换网络/DHCP 续租）：旧二维码失效。在网站里改成新 IP 保存，二维码立即更新，无需重新发布问卷，Token 不变。
- **电脑关机 / Vite 停止**：手机打不开页面。重启 `dev:lan` 后原二维码继续有效（Token 与 IP 未变的话）。
- **后端 8080 停止但 Vite 在跑**：页面能打开但接口报“请求超时/503”，恢复后端即可。

## 9. 安全边界（务必阅读）

- **二维码 = 分享链接 = 参与凭证**。同一网络内任何拿到二维码的人都能填写。发错对象时用“重新生成分享链接”轮换，旧码立即失效（已在填写中的会话不受影响，仍可完成提交）。
- **不要在不受信任的公共 Wi-Fi 上开 `dev:lan`**：Vite dev server 未做生产级加固（无 HTTPS、无访问控制），同网任何人可访问页面与 `/api`。仅在你自己的热点/家庭 Wi-Fi 等受信任网络使用，用完切回 `npm.cmd run dev` 或关闭热点。
- 局域网分享时问卷内容以 HTTP 明文传输（局域网内可被同网嗅探）。M1 阶段问卷不含实名信息；未来公网部署需 HTTPS（链接配置已预留 `https://` 域名支持）。
- 管理登录、统计、轮换等操作仍只允许发起者账户；手机受访者匿名填写，无法看到他人数据或统计。

## 10. 常见问题

| 症状 | 原因与处理 |
|---|---|
| 二维码区域显示“未配置局域网地址” | 按 第 2–3 节 配置电脑 IPv4 |
| 手机扫码后一直转圈 | 不同网 / IP 变了 / Vite 没用 `dev:lan` |
| 手机提示“无法访问此网站”但能上网 | 防火墙未放行 5173（第 5 节）或 AP 隔离（第 4 节） |
| 换到电脑热点后二维码失效 | 热点 IP 与 Wi-Fi IP 不同，改配置即可（第 3 节第 5 步） |
| 误把 localhost 填进配置 | 会被拒绝；填真实 IPv4 |
| 想作废已发出去的二维码 | 发布记录 → “重新生成分享链接”（旧码立即失效） |
