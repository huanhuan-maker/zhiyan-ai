## D. Token轮换、重试和响应丢失（P1-02）

- [ ] 对一个OPEN版本，在轮换前保留一份匿名在途会话；所有者点“重新生成分享链接”并确认，复制新链接。
- [ ] 旧链接GET及新建匿名会话404，新链接可访问；轮换前合法建立的在途会话仍可提交，轮换不清空原答案。
- [ ] 在两管理标签都读取相同发布记录后，只让标签A轮换成功；标签B基于旧 `shareRevision` 轮换应409，不能废掉A刚复制的链接。
- [ ] F12 Network选中轮换请求，**仅在自己的本地合成调查上**重发相同JSON `expectedShareRevision`：第一次成功后的重放应409 `STALE_SHARE_LINK`，审计只增加一次成功轮换。
- [ ] 模拟“服务端已成功提交，但客户端没有收到成功响应”：可结合本机代理/测试工具丢弃响应；若只执行 `Verify-M1Publication.ps1`，应记为“成功响应丢弃后重放模拟”，不能写成真实断网/丢包已验证。
- [ ] 响应丢失后不自动重试生成其他token；用户先重新读取发布记录，再明确确认轮换，得到另一条可用链接；这会使丢失响应中的链接失效。旧标识重试不得再次改token。
- [ ] 禁止localStorage时，成功响应的新链接仍在当前页可手动复制，并提示没有保存；刷新后可通过明确轮换恢复。
- [ ] 无登录/无CSRF拒绝；另一用户携合法CSRF调用也404，不能只测试缺CSRF的403；不能跨调查指定版本轮换。
- [ ] 分享链接/匿名token不出现在日志或审计截图中；管理API返回不可用于读他人答卷。

前置条件不是成功响应缓存：数据库只留摘要，不能用同请求重取同一明文token。409是保护性冲突，不是虚假成功。无需把token/密码发给Agent。
