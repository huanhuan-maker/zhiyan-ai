# M5-E：问卷知识库与检索后分析

本轮按用户要求提供可运行的第一版：侧栏“问卷知识库”、当前账号发布版本资料入库、检索预览，以及助手在检索后调用真实 LLM 回答。仍使用 Vue 3、Spring Boot、MyBatis-Plus、MySQL 8；图表沿用 ECharts。

## 页面内容

- 资料集：当前账号最近 100 份已发布问卷的最新版本，索引状态、上次同步时间、当时的答卷数与资料片段数。
- 手动同步：按冻结发布版本建立资料快照；列表中的数量是上次同步数量，并非后台持续实时更新。
- 检索体验：切换发布版本、输入问题、查看匹配或用于多样性覆盖的资料片段、匿名答卷编号和题目编号。
- 向助手提问：保留问卷、版本和问题，用户点击发送；助手先校验当前答卷指纹，有变化时更新索引，再检索并分析。
- 模拟数据标记、覆盖限制、向当前模型发送检索片段的提示。

## 实际数据链路

MyBatis-Plus 读取所有权 → 冻结版本和一致性统计快照 → 过滤显式个人信息题目、遮蔽常见手机/邮箱/证件号 → `fm_survey_knowledge` 保存版本资料 JSON 与源指纹 → 中文二字片段相关性排序、开放题覆盖和相似文本去重 → 选取至多 12 条资料，结合本版本后端统计，按当前模型输入预算选取完整来源并显示实际统计覆盖数 → 当前配置 LLM 输出分析段落与引用 → 校验引用存在、数字出现在该段引用的资料中 → 保存聊天历史并展示可点击来源。

这是真实的检索增强生成流程。第一版使用字符片段检索，没有配置嵌入模型或向量数据库，不声称向量语义检索或跨问卷语义分析。知识库是可检索的持久化资料快照；本轮不是 Wiki 知识编纂系统。

## 接口和工具

- `GET /user/form/knowledge`：当前账号最新发布版本资料集列表。
- `POST /user/form/knowledge/sync`：`formKey, version?`，同步并展示资料预览。
- `POST /user/form/knowledge/search`：`formKey, version?, question`，查询前核对数据更新。
- MCP `survey_knowledge(formKey, version?, question)`：同步、检索、后端统计与 LLM 综合回答。已有查询、管理预览和确认机制保持有效。
- 修改 MCP 过滤器，将已验证的账号绑定到当前请求供统一模型配置服务读取，并在结束后恢复上下文，避免报错“登录失效”和线程身份残留。

## 边界

- 仅当前账号自己的问卷，管理员也没有跨账号知识库查询特权；归档后知识库接口与关联历史结果均不可见。
- 暂存和未发布草稿不作为调查结果入库；发布版本分开存储。
- 复用现有分析快照上限：单版本最多 5000 份答卷；最多 200 条开放回答、单条不超过 2000 字、总计不超过 60000 字。超出部分显示数量，不能把入选片段数解读为总体人数。
- 当前仅入库题目背景与 INPUT/TEXTAREA 原文；选项、量表的总体统计由后端提供。没有交叉统计工具，不推断不同年级等群体间差异。
- 模拟标记依据入选回答中的“模拟测试”或 Synthetic 文本识别，不作为完整的样本来源审计字段；混合真实和模拟数据时明确提示包含模拟数据。
- 常见联系方式过滤不是完整匿名化；自由文本仍可能包含其他识别信息。
- 模型失败或输出不合法时只保留来源，不伪造分析；没有答卷时不调用模型生成调查结论。
- 引用与数字合法性检查不能证明每句话的语义推断正确，分析可由用户沿来源复核。未自动变成已审核报告。
- 上下文预算包含所配置输出上限和保守 UTF-8 输入估算；容量不足时选取完整资料而非截断原文，并显示提供了多少道题的统计。模型第一次输出校验失败时最多重试一次，网络失败不重复等待。
- 每次分析重新检索；暂不做后台索引队列、嵌入模型配置、跨问卷综合、交叉统计、完整研究 Wiki 或真实流式回复。
