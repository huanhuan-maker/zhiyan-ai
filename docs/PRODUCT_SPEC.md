# 知研 AI — 产品需求规格 V1.0

## 1. 定位与范围
通用 AI 调研平台；发起者不需具备专业问卷或统计学背景。主流程：描述目标 → 生成/编辑问卷 → 发布 → 受访者填固定题 → 按需开放题追问 → 汇总统计与新维度 → 可追溯报告。

研究核心：在有限追问预算、避免诱导、尊重受访者意愿的约束下，增加有效且不重复的信息，发现预设问卷中遗漏的相关新维度。

## 2. 产品角色
- 调研发起者：注册/登录，管理自己创建的调查、编辑草稿、审核 AI 生成问卷、发布、查看与导出结果、复核新维度。
- 受访者：通过公开链接访问，查看隐私说明，填写题目，自主回答或跳过追问，可中断及提交。默认不强制登录。
- 系统管理员（基础）：平台运行与数据治理；无必要不浏览用户答卷内容。

## 3. 关键用户旅程
### 3.1 发起者
1. 输入自然语言调查目标、目标人群（可为空）、想了解的问题（可为空）、题目数量上限、预计时长；AI 可以询问必要的澄清信息。
2. AI 生成问卷草案（题目、题型、必填标记、选项、固定核心与开放题追问许可）。
3. 发起者编辑/删除/排序，设置标题、简介、隐私声明、截止时间、匿名策略、追问预算（默认每个开放题不超过 1 次、整份最多 3 次，可配置）。所有设置在发布前确认。
4. 发布得到稳定链接与不可变 `survey_version`；后续若需要改核心题，必须形成新版本，不得悄然覆盖原版数据。
5. 查看回收数、完成人次、有效核心题统计、开放题主题；浏览具体证据并对“新维度”执行接受、重命名、合并、驳回。
6. 查看由确定性统计计算与 AI 有据解释组成的报告；导出 CSV/JSON 与报告（MD/HTML/PDF 可后续）。

### 3.2 受访者
1. 打开公共链接，看到调查说明、预计时长、AI 可能追问、隐私政策与是否匿名；同意后开始。
2. 顺序填写核心题（单选、多选、量表、开放文字为 V1 题型），可保存过程以便刷新恢复（实现方式遵守隐私设计）。
3. 在有追问权限的开放题提交回答后，系统评估“跳过 / 澄清 / 深入 / 探索”动作。
4. 如显示追问，必须可跳过；不暗示受访者应当回答某观点；不强制多轮；明确显示进度和预计剩余时间。
5. 确认提交后看到成功状态，不得重复计算。AI 超时/断开时继续核心问卷填写，追问可降级跳过。

## 4. 动态追问的硬边界
- 已发布核心问卷内容和顺序冻结；追问不得反向改写核心回答。
- 追问只能与调查目标/受访者自身回答相关；不得凭空插入受访者未提及的具体动机并要求其认同。
- 受访者明确拒绝、跳过、达到次数/时间预算、隐私风险高、模型输出不符合 Schema 或请求失败 → 不继续追问。
- 追问可用于澄清模糊、获得实例/原因/情境、探索受访者**自己提出**的相关新维度；不以字数阈值判断是否追问。
- 最多一次追问显示为一个独立问题；预算默认每开放题 1 轮、全问卷 3 轮（只是可配置默认，不是实验证实的最佳值）。
- 信息充分也可探索，但需要有潜在价值的证据；单纯“还可以多问点”不足以触发。

## 5. 新维度发现（跨受访者）
- 从已完成的同意分析的开放回答和追问记录中离线/异步按批次发现主题。
- 主题聚类必须保留证据定位：受访会话匿名 ID、源题 ID、原始/追问文本片段、来源类型。
- 主题来源强制区分 `SPONTANEOUS`、`NEUTRAL_PROBE`、`SUGGESTED_OPTION`、`MODEL_INFERRED_UNCONFIRMED`。未被人确认的推断不得算作用户观点。
- 主题状态：待核实线索 → 候选维度 → 多案例支持 → 待验证假设 → 经独立验证。系统不能自动标记“经独立验证”。
- 发起者可审核、合并拆分（拆分可放 M3 后段）、重命名、驳回；所有操作保留审计。
- 不在调查进行中自动修改核心题；不根据其他受访者的发现去暗示当前受访者的回答；本轮不做在线跨人验证实验。
- 主题报告分开统计自发提及与追问后提及；出现比例的分母必须明确，不将条件性追问主题频数推断为总体患有/具有某观点的比例。

## 6. 报告和数据可信度
- 选择题、量表题统计由后端确定性查询/代码计算；缺失值、有效答卷、问卷版本与分母显式展示。
- 开放题采用主题归纳，给出证据示例和对应匿名记录；不生成虚构引用。
- 不把“主题出现次数”直接写成受访总体的观点比例；没有随机抽样不做总体代表性保证。
- 允许展示 AI 的分析建议，但区分“原始事实”“计算结果”“模型解释”“待验证假设”。

## 7. 隐私与业务要求
- 按调查项目隔离数据；受访者端只能访问当前公开问卷，不得查看其他人的回答。
- 公开填写限制请求频率，防机器人刷票的控制不能默默剔除合法回答。
- 默认只收集调查必要字段；不要求真实姓名。调查发布前提示敏感问题收集风险。受访者须知道 AI 可能处理其文本。
- 模型 API Key 服务端存储；对真实回答的模型传输应有明确数据处理告知。日志不得打印原文、token、隐私字段。
- 导出、删除、停用公开链接、访问控制、审计日志至少具备基础实现。

## 8. 验收案例（必须可复现）
A. 发起者创建 1 份食堂满意度调查，编辑 2 道选择题 + 1 道开放题，发布后可从手机访问。
B. 受访者写“食堂不太方便”，系统给出 1 个中立澄清追问；受访者选择跳过也能提交。
C. 受访者写“晚上 6 点二楼排队 15 分钟，喜欢的菜卖完”，系统可决定跳过或基于预算进一步探索，但必须记录原因。
D. 受访者主动提出“朋友不去图书馆影响我”，系统可提炼“同伴影响”；原问卷只有环境/座位/开放时间时，聚合分析列出该新维度并附原文，不扩写到其他人。
E. AI 不可用时，普通问卷创建（手工）与受访者填写、提交、统计仍可使用。
F. 修改已发布调查必须新增版本；旧答卷仍可按正确问卷版本查看。
G. 报告任意统计数字必须能定位计算分母/条件；任何主题证据必须能找到来源文本。

## 9. 本次不做
自动变更进行中的核心问卷；跨人实时新假设验证；全聊天式访谈；问卷采购/付费；任何未经确认的所谓 Jev 概率代表“受访者持该观点的概率”；处理医疗诊断等高风险专业意见。
