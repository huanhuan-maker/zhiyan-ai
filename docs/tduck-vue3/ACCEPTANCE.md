# 第一阶段人工验收

使用独立开发库和新前端，不对 8999 的原部署做试验。启动见 `tduck-vue3/README.md`。验收数据明确标为 acceptance fixture，不是真实受访者信息。

1. 访问 `http://127.0.0.1:5180`，输入本地 `.local/tduck-dev/acceptance.json` 的 owner/password。应进入 Vue 3 工作台；错误密码应提示且不进入后台。
2. 列表应有 3 份根目录合成问卷和 1 个文件夹；状态图为三个状态各 1，总数为 3，不含文件夹与子目录。所有值来自后端 total。
3. 搜索 Learning habits，再选“未发布”，应得到空结果。清除搜索/状态后恢复原结果；打开 Archive 可见子目录问卷。
4. 点击问卷名称或查看详情，核对问卷名、时间及题目文字，刷新应仍能读取。详情是只读元数据，不应出现设计/发布假按钮。
5. 退出后访问详情应回到登录；用 other 账号登录，再直接访问 owner 的问卷地址，应提示无权限，不能显示题目，且 other 账号仍保持登录。
6. 浏览器测试已有真实后端无效 Token 验证及离线故障注入。也可在浏览器 Network 中观察请求确实经 `/tduck-api`，密码只在登录请求体，Token 只在请求头。
7. 在 390px 宽屏或手机尺寸检查菜单、列表、详情和退出；无需开放局域网或修改防火墙。
8. **重启持久化待人工执行**：在自己启动的开发后端终端 Ctrl+C 正常停止，然后重新运行 `scripts/tduck/Start-Backend.ps1`；刷新前端，重新登录，再运行 `scripts/tduck/Verify-HTTP.ps1`，应仍有相同题目/列表。不要关闭原 TDuck 服务。

本轮自动验证为 25 单元 + 9 浏览器 + 15 HTTP 项，具体报告与截图见 `evidence/tduck-vue3/M0.md`。人工验收尚未由用户完成；不能据此开始设计器/AI 阶段。若判定 FAIL，先补回归并修复当前阶段。
